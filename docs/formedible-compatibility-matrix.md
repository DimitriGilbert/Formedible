# Formedible Legacy API Compatibility Matrix

This matrix records the compatibility status restored during the Formedible regression phases. It is intentionally narrow: the package supports the old API surface listed here only where behavior is typed, rendered, or preserved by current tests.

| Legacy API surface | Status | Current behavior | Alignment tests |
| --- | --- | --- | --- |
| `section` | Restored | String sections render as headings. Object sections render `title` and `description`, interpolate dynamic text, and avoid duplicate adjacent headers per page/tab. `collapsible` and `defaultExpanded` are intentionally unsupported; section metadata is rendered as static grouping UI. | `tests/formedible/section-rendering.test.tsx`, `tests/formedible/normalize-field-config.test.ts`, `tests/formedible/types/options.test-d.ts` |
| `textareaConfig` | Restored | `rows`, `cols`, `maxLength`, `resize`, and `showWordCount` are typed and rendered. Top-level `rows` and `maxLength` take precedence over nested legacy config. | `tests/formedible/basic-fields.test.tsx`, `tests/formedible/types/field-config.test-d.ts` |
| `passwordConfig` | Restored | Password fields use a dedicated password component. `showToggle`, `strengthMeter`, and `minStrength` are typed and rendered; unsupported keys are rejected by type tests. | `tests/formedible/basic-fields.test.tsx`, `tests/formedible/types/field-config.test-d.ts` |
| Direct field validation schema | Restored | Field-level `validation` accepts function validators, `{ validator, message }`, and Standard Schema / Zod-like schemas. Schema validation is recognized without treating arbitrary objects as validator wrappers. | `tests/formedible/validation/validation-pipeline.test.tsx`, `tests/formedible/types/field-config.test-d.ts` |
| `autocomplete` / `autocompleteConfig` | Restored | `type: 'autocomplete'` renders the autocomplete component instead of degrading to plain text. Static `autocompleteConfig.options`, async options, debounce/min/max controls, custom values, placeholders, loading text, and empty text are supported. Nested options take precedence over top-level fallback options. | `tests/formedible/advanced-fields.test.tsx`, `tests/formedible/types/field-config.test-d.ts` |
| `masked` / `maskedInput` | Restored | `maskedInput` normalizes to `masked`. Top-level `mask` and `maskedInputConfig.mask` support string masks and formatter functions. Legacy `showMask`, `guide`, `keepCharPositions`, `placeholder`, and `pipe` behavior is typed and covered. | `tests/formedible/advanced-fields.test.tsx`, `tests/formedible/normalize-field-config.test.ts`, `tests/formedible/types/field-config.test-d.ts` |
| Custom field `component` / `wrapper` | Restored | Field-level component overrides and wrappers use typed render/controller contracts and preserve access to the default renderer. | `tests/formedible/basic-fields.test.tsx`, `tests/formedible/types/field-config.test-d.ts` |
| Form-level `defaultComponents` / `globalWrapper` | Restored | Form-level default components override registry rendering by normalized field type. `globalWrapper` wraps rendered fields through the same typed wrapper contract. | `tests/formedible/basic-fields.test.tsx`, `tests/formedible/types/field-config.test-d.ts` |
| Form options | Supported / restored / removed | Current options remain supported. Restored options include `onPageChange`, `autoSubmitOnChange`, `autoSubmitDebounceMs`, `disabled`, `loading`, `showSubmitButton`, form DOM event handlers, labels, and `formClassName`. `onSubmitInvalid` is intentionally removed and superseded by TanStack Form validation state and rendered errors. | `tests/formedible/basic-fields.test.tsx`, `tests/formedible/types/options.test-d.ts` |
| Analytics | Supported / superseded | Runtime-supported callbacks include form start, field focus/blur/change/complete/error, page change, form complete, form abandon, and form reset. Page completion/abandon/validation analytics, tab analytics, render performance, validation performance, and submission performance callbacks are superseded and rejected by type tests. | `tests/formedible/basic-fields.test.tsx`, `tests/formedible/types/options.test-d.ts` |
| Parser/storage preservation | Supported with serialization limits | Active AI storage/export paths preserve supported JSON-safe canonical configs, including section metadata, textarea/password/number/autocomplete/masked/color config, form options, and safe schemas. Function-backed configuration is not persisted; callbacks, component boundaries, async option functions, schema functions, validation functions, and analytics functions are omitted deliberately. | `packages/ai-builder/src/lib/formedible/ai-storage.test.ts` |
| Old Array fields form schema/config | Supported with import-path migration | The old Array fields schema and field config typecheck and build in a fresh shadcn Vite base app after updating the hook import from `@/hooks/use-formedible` to the installed registry path, `@/components/ui/formedible/hooks/use-formedible`. | `pnpm run test:consumer-smoke:vite-base` |

## Additional audited decisions

- `numberConfig` is restored for native `min`, `max`, and `step`. Legacy precision-style behavior is intentionally unsupported because the native number input path does not consume it.
- `datalist` and `help` are restored for text-like compatibility examples. `emailConfig` is intentionally unsupported; use schema-level validation or field-level `validation` for email rules.
- `colorPicker` remains a compatibility alias for `color` and preserves `colorConfig` behavior.
- Parser/storage preservation is not a behavior execution boundary. It stores only serializable configuration needed to reconstruct supported form shape safely.
- shadcn registry installs place Formedible under the configured `@ui` alias. With the base Vite preset used by the smoke test, that resolves to `@/components/ui/formedible`; old form code should update imports, not schema or field configuration.
